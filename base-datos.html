Base de datos · Oracle Cloud

Modelo de datos de PetCore

50 tablas en Oracle, gestionadas con SQL Developer, siguiendo el estándar SCREAMING_SNAKE_CASE: TBL_<ENTIDAD>, prefijo de columna por tabla, y constraints nombradas PK_ / FK_ / UQ_ / CK_ / IX_. El script se ejecuta de arriba hacia abajo porque ya respeta el orden de dependencias de llaves foráneas.

Relaciones clave

Cómo se conecta todo: el flujo clínico completo

Si el jurado pide dibujar el flujo de una visita veterinaria en la pizarra, este es el camino real por las tablas:

PROPIETARIO → MASCOTA → CITA → CITA_SERVICIO → EXPEDIENTE → DIAGNOSTICO_EXPEDIENTE → PRESCRIPCION → DETALLE_PRESCRIPCION → MOVIMIENTO_INVENTARIO

Un propietario tiene mascotas → la mascota agenda una cita (que puede incluir varios servicios, de ahí la tabla intermedia CITA_SERVICIO, relación muchos-a-muchos) → el veterinario abre/actualiza el expediente de la mascota → registra un diagnóstico ligado a ese expediente → si hace falta medicar, crea una prescripción con sus detalles (fármaco + posología) → al despachar la receta en farmacia se genera un movimiento de inventario que descuenta el stock del producto.
